# ADR — M4 Replay Lab and Run Artifacts

## Status

Implemented for M4, awaiting owner acceptance.

## Decision

1. **Run artifact format** (`packages/simulation/src/artifact.ts`, `null-city-run-artifact` v1) is a new module alongside `receipt.ts` rather than a rewrite of it — the M0 receipt format stays untouched and `verify:receipt-slice` keeps passing unmodified. A `RunArtifact` carries: scenario/engine/session identity (including `scenarioDigest` and `engineProtocolVersion`), the full verified truth event log **and** the full verified player event log, a re-derived `commandTrace` (from `CommandIssued`/`CommandAccepted`/`CommandRejected`) and `assessmentTrace` (from `AssessmentSubmitted`), terminal hashes for both streams, a `stateDigest`/`scoreDigest`, an optional detached `signature` metadata field (`{algorithm, keyId, signature} | null` — never itself verified cryptographically here, since no trusted root key exists yet; a hash chain is tamper-evident only), and a self-referential `artifactHash` over the canonical JSON of everything else. `buildRunArtifact` refuses to build unless the truth log actually ends in `ScenarioCompleted` — there is no code path that produces an artifact for an active run.
2. **Strict runtime parsing lives in two places on purpose.** `packages/simulation/src/artifact.ts` (`parseArtifactJson`) is the Node-side parser used by the CLI and server; it bounds input to 64MB and validates shape before trusting any field. `apps/command-center/src/replay/schema.ts` (`parseReplayArtifact`) is a **second, independent, clean-room parser** for the browser, because player-facing code may not import `@null-city/simulation` or truth-only types from `@null-city/contracts` (enforced by `apps/command-center/test/forbidden-imports.test.ts`). The browser parser defines its own structural `ReplayTruthEvent` type rather than importing the forbidden `EventEnvelope`/`EventKindName`/truth-payload types by name.
3. **The browser never trusts the server's "200 OK".** `@null-city/contracts`'s `sha256`/`canonicalJson` use `node:crypto`, which is unsafe to pull into a Vite bundle (and unavailable via `crypto.subtle` in the `jsdom` test environment). `apps/command-center/src/replay/hash.ts` reimplements SHA-256 and canonical JSON from scratch in pure JS (verified byte-for-byte against `node:crypto` in `replay-hash.test.ts`, including on a 1MB input to exercise the 64-bit length field), and `replay/verify.ts` reimplements the same hash-chain, terminal-digest, `artifactHash`, and command/assessment-trace-equality checks as `packages/simulation/src/artifact.ts`'s `verifyRunArtifact`. Replay Lab always calls this independent verifier and shows PASS/FAIL plus a caveat that a valid chain is tamper-evident only, not proof of authenticity.
4. **The epistemic boundary gains one sanctioned exception, gated on server-side phase.** `packages/server/src/rpc.ts` adds a `session.artifact` op (exposed at `GET /sessions/:id/artifact` in `http.ts`) that throws `not_completed` (mapped to HTTP 409) unless `engine.worldState.phase === "completed"`; there is no other path to the truth bundle. `packages/server/src/artifact.ts` wires `buildRunArtifact` to a session's real engine + bridge state. `packages/server/src/cli/verify-artifact.ts` (`pnpm verify:replay-lab`) proves this end-to-end against a live server: an active session is denied (409/`not_completed`), a completed session's artifact independently verifies, tampering any field is rejected, the player projection rebuilt from the artifact's player log alone reproduces the same score/phase, and a from-scratch re-simulation of the embedded truth log (`replayResult`) reproduces the same terminal event-log hash and state digest — i.e. the truth log is re-derivable, not just replayed blindly.
5. **CLI tooling**: `packages/simulation/src/cli/run.ts` (bin `null-city-run`) adds `run verify`, `run inspect`, and `run compare` subcommands over artifact files, independent of the server. `pnpm verify:artifact-cli` (`scripts/generate-m4-artifacts.mjs`) generates two real completed-run artifacts over HTTP and drives all three subcommands against them as part of `pnpm verify`.
6. **Replay Lab UI** (`apps/command-center/src/routes/ReplayLabPage.tsx`) fully replaces the M3 placeholder. It loads an artifact either from a completed session (`restApi.artifactRaw` + `unwrapArtifactEnvelope`) or a dropped/selected file (`ArtifactLoader`, which rejects oversized files by `file.size` before ever reading them, and shows the parser's rejection reason for malformed ones). Once loaded and independently verified, it renders:
   - a tick-scrubber timeline with marks for score changes, evidence delivery, and commands (`TimelineScrubber`);
   - player-visible state and truth state **side by side** at the current tick (`DualStatePanel`), with the truth column always tagged "post-run reveal" — truth projection (`replay/project.ts#projectTruthAtTick`) is rebuilt purely from the artifact's own truth log, has no equivalent in any live/running code path, and only exists inside Replay Lab;
   - an evidence provenance / distortion detector (`EvidenceProvenancePanel`) that traces each piece of public evidence back to the `ObservationCreated`/`ObservationCorrupted`/`ObservationDelayed` truth events that produced it, flags corrupted or delayed items, and shows the original vs. reported content side by side — this is what lets a commander point at a specific false or late report and the claim it influenced;
   - an action/team-movement timeline merging `commandTrace` with `TeamDispatched`/`TeamArrived`, and a score-delta timeline linking every `PublicScoreChanged` event back to its tick;
   - a compare mode (`CompareRunsPanel`) that loads a second artifact the same way and diffs score/tick/incidents/commands, flagging when the two runs don't share a scenario digest;
   - a Markdown report export (`replay/report.ts`) built only from data already rendered — verification status, the distortion table, the command trace, and (if loaded) the comparison.

## Consequences

- `packages/simulation` gains `@null-city/epistemics` as a **dev**-only dependency (used solely by `artifact.test.ts` to build a realistic player event stream via `TruthToPlayerBridge`); it is not a production dependency of the simulation package, and the simulation package's public surface still has no epistemics-aware code.
- `apps/command-center`'s production dependency graph is unchanged (`@null-city/contracts` types only); `apps/command-center/test/forbidden-imports.test.ts` still passes with zero exceptions carved out for Replay Lab.
- `pnpm verify` gained `verify:replay-lab` and `verify:artifact-cli`; both run before `verify:command-center` so a broken artifact contract fails fast, before the UI-level gate.
- `apps/command-center/e2e/smoke.mjs` now also asserts the artifact endpoint is blocked pre-completion and released post-completion with a well-formed shape, over a real running server.

## Unverified / deferred

- No trusted external signing key exists yet, so the `signature` field is metadata-only; authenticity beyond tamper-evidence is out of scope for M4, as called out both in the UI and in the exported Markdown report.
- No Playwright browser automation drives the Replay Lab UI directly; coverage is unit/integration-level (`replay-*.test.ts`, 39 new command-center tests) plus the server-side artifact lifecycle (`verify:replay-lab`) and the REST-level e2e smoke script. A full interactive walkthrough is available via `pnpm demo`.
- Compare mode is informational-only when the two artifacts don't share a scenario digest (no attempt to normalize across different scenario content).
