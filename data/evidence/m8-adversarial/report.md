## Accepted limitations (reproduced, not fixed)

- **A2-05 (P2)** session.list enumerates every other live session to any client
  - observed: a WS client scoped to adv-ws-attacker enumerated 2 foreign session ids (adv-victim, adv-ws-victim)
  - accepted because: GET /sessions is a documented endpoint of an unauthenticated, loopback-only, single-user tool: any local process that can call it can already call every other endpoint. Session ids are therefore identifiers, not capabilities. Adding authentication is explicitly a v0.1 non-goal (00_NORTH_STAR.md). Recorded in docs/threat-model.md.
- **A6-07 (P3)** the server enforces no ceiling on concurrent sessions
  - observed: all 60 sessions were accepted with no cap; each holds a full engine and event log in memory
  - accepted because: Only reachable by a process already on the loopback interface, which can exhaust memory by simpler means. A cap would break the benchmark matrix, which legitimately opens many sessions. Revisit if a shared or hosted deployment is ever in scope (it is a v0.1 non-goal). Recorded in docs/threat-model.md.
